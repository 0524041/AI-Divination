# 占卜紀錄即 Thread，SSE 串流全面取代輪詢

原架構中一列 History 只能承載一問一答、前端以 2 秒輪詢取回完整字串，使「連續對話」在資料模型與傳輸層都不可能。決定：**占卜紀錄為 Thread 根節點**，新增訊息表承載 解盤＋追問序列；所有 AI 回應（含首次解盤）一律經 **SSE 逐 token 串流**送達，廢除輪詢與 pending/processing 前端狀態機；等待感交由各占卜類型的儀式動畫承擔。既有的單一 `interpretation` 欄位資料自動遷移為該紀錄的首則助手訊息。

## Considered Options

- 保留背景任務＋輪詢、僅追加追問端點——拒絕：兩套傳輸機制並存，取消／重試／錯誤語意得維護兩份。
- WebSocket 雙向通道——拒絕：單向串流即可，SSE 更簡單且前後端鷹架皆已存在。

## Consequences

取消語意改為「中止串流生成」；分享頁改渲染訊息流（原靠數 `----` 分隔線解析文字的 hack 一併廢除）。
